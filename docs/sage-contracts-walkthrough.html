Model consistencyThe declared graph respects its own rules.
Source correspondenceSage items have compatible Rust anchors, and annotations resolve in the right crate.

The first two cover the current model. Runtime enforcement is proven on isolated fixtures and a narrow production signature scope; full compiler-body coverage is unfinished.

01 / Review stop

Start with three operations

Read this small test model first. Root::run may call Helper::work, and forbids reaching Leaf::read through any nonempty call path. Helper has an empty envelope.

The model is consistent because the permitted graph never reaches Leaf. The Rust fixture will deliberately take an undeclared edge. This lets us test runtime failure without making the model itself invalid.

Review the abstraction

An invokes entry is permission, not a required call or execution order. An empty envelope makes Helper a leaf at this architectural level; it can still perform internal work and read fixture inputs.

03 / Review stop

Check correspondence in both directions

CorrespondenceIndex::load uses Cargo ownership and parses Rust syntax. Its index records the Sage identity, declaration kind, Rust path, file span, target, and cfg conditions. The validator then joins it to the model’s crate/module headers, declarations, and explicit methods.

Kind checks follow: a method may map to a function, a method, a trait method, or a module anchor. The report separates source sites from declarations with executable bodies. A cfg inventory is not a claim that every alternative exists in this binary.

cargo run -p sage-meta -- check --correspondence --json
What a green audit establishes

At this revision, all 194 model units have anchors across 203 Rust sites. Of those sites, 52 have function bodies. This validates correspondence; it does not prove that every compiler call follows its envelope.

When a query is observed, lookup ↗ accepts one matching executable declaration at its original file/line. Missing and ambiguous matches are failures. An unannotated nested function cannot borrow its enclosing function’s Sage identity.

Review source-index tests ↗ for cfg alternatives, declaration kinds, nested functions, known generators, and rejected conditional annotations.

04 / Review stop

Check one architectural stack

ContractModel resolves the same names, inheritance, and virtual call targets as the static validator. A checking session owns an explicit set of allowed roots, its active invocations, a trace, violations, and coverage gaps.

A source request is checked against the active caller. Every observed request or internal reexecution is also checked against all active ancestors’ prohibitions. Entering the same operation again counts as recursion.

Collect prohibitions from every active ancestor

A self permission requires matching receiver identities. Different receivers produce a violation; missing identity produces a coverage gap. The result retains the offending call path and the rule’s location in the model.

Review the success criterion

calls_conform is scoped to observed boundaries. Reads and context creation are recorded as unchecked effects. A warm memo’s historical dependency graph is not replayed.

05 / Review stop

Join Salsa events to that stack

Salsa’s query definition supplies original source provenance. The observer matches that location against the Rust index and caches the result by ingredient identity. Query debug names are not used for matching.

The tests supply include_str! snapshots of the relevant Rust files. Reading two current disk copies would not establish compatibility with the running binary. A stale or unpaired source cannot silently pass.

The two stacks

The raw lifecycle stack verifies request/execution nesting. The architectural stack checks modeled operations. A normal request plus its execution produces one architectural invocation. Internal reexecution establishes its own context and still inherits active prohibitions.

The production database forwards raw events before display-log coalescing ↗. RAII guards balance execution events on unwind. The vendored macro change preserves each tracked method’s source span, so methods in one impl remain distinguishable.

      07 / Review stop

      Inspect the cached forbidden call

      The fixture flips violate to make Helper call forbidden. Two separate rules fail: Helper never declared permission to call Leaf, and Root forbids Leaf transitively.

      The precise guarantee

      The cached Leaf request is checked even though its body does not execute. This does not establish the hidden descendants of an entirely reused parent memo. The test deliberately forces Helper to make the leaf request in the observed session.

      Violations are retained as data. The adapter does not panic inside Salsa callbacks. Callers enforce a checked run with assert_calls_conform() at the report boundary; this negative fixture instead asserts the expected violations. This preserves both diagnostics and lets query unwinding close the active frames.

      Review missing or swapped annotations ↗, stale or ambiguous sources ↗, panic cleanup ↗, and malformed lifecycle replay ↗ for ways the checker must refuse success.

      The next implementation decision

      Choose how ordinary methods emit boundaries and how receiver identity crosses those boundaries. The current Salsa adapter supplies None for receivers. Async/task propagation, reads/creates enforcement, full body conformance, and agent transports are still staged work.

      The final command serves the existing architecture explorer at 127.0.0.1:3001. It browses declarations and their source links; it does not yet replay runtime reports.
